# Market Updates Phase 9 — frontend recovery

The workspace keeps independent, partial reads for published updates, authoritative health and digests, preserving previously loaded content when one refresh fails. Empty states are now mutually exclusive and driven by registry, enabled-source, run, candidate, publication and actual-filter state; Clear filters is rendered only when a non-default filter is active.

Operational cards include authoritative counts, latest model/route, duration and next eligible fetch. Sync actions expose safe run identity and progress counters and follow reused active runs. Administrators can open a read-only candidate review surface. The source dialog adds search and status filtering while retaining its responsive, vertically scrolling, overflow-safe layout.

This repository phase has not been deployed or browser-verified because the local frontend toolchain is unavailable. Live responsive and network acceptance remains required.
