# PDF Extraction V3 · E12 — Golden Corpus, End-to-End Regression Harness and Formal Release Gates

> **Status:** CODE ONLY · the final code package of the PDF Extraction V3 roadmap · no deploy. Builds on
> the merged E0–E11 foundation and certifies release-readiness with GENERATED evidence and STRICT gates.

## 1. Problem statement

The earlier Golden Corpus + release-gate system was V1: broad legacy categories, thresholds that could
pass on manual review, a static gate that returned exit 0 for skipped checks / pass-with-warnings, and
no generated end-to-end corpus. E12 replaces that with a formal certification system that generates a
reproducible artificial corpus at test time, exercises the REAL E0–E11 pipeline (real source PDF →
real E6 render in Chromium → real DOM + browser raster → real jsPDF export → real export re-parse),
applies hard-defect-first acceptance, and never turns a skipped/warning/unavailable required check into
a release pass.

## 2. Non-goals

E12 does not improve extraction, add a provider, or loosen any E4/E5/E7/E8 threshold to pass tests. It
does not activate E10 routing, remote providers, Document AI or VLM; create cloud resources; commit
private documents; auto-approve baselines; treat a forced operator override as an automatic pass; turn
warnings/skips into passes; retry quality failures until they pass; use AI/OCR/PDF-text as proof of
visible output; or compare the candidate to itself as source fidelity.

## 3. Contract versions

`pdf-golden-corpus-registry-v2`, `pdf-generated-fixture-spec-v1`, `pdf-private-corpus-registry-v1`,
`pdf-golden-expected-truth-v1`, `pdf-golden-run-manifest-v2`, `pdf-golden-run-result-v2`,
`pdf-golden-suite-result-v1`, `pdf-release-gate-policy-v2`, `pdf-release-gate-report-v2`,
`pdf-release-baseline-v2`, `pdf-release-determinism-report-v1`, `pdf-release-performance-report-v1`,
`pdf-release-artifact-manifest-v1`, `pdf-release-readiness-v1`. Plus `pdf-source-builder-v1` and
`pdf-release-thresholds-v2`.

## 4. Release tiers

| Tier | Purpose | Browser/Export | Strictness |
|---|---|---|---|
| **static** (1) | fast PR: scan + contracts + pure suites | no | required checks must pass; build/browser deferred to owning jobs |
| **generated-fast** (2) | mandatory PR end-to-end (small generated fixtures) | **yes** | skipped=fail; one advisory warning code allowed |
| **generated-full** (3) | main/nightly full corpus + 25/80-page + determinism + perf | **yes** | warning/skip/unavailable all = fail |
| **private-controlled** (4) | approved private corpus, manual/trusted only | yes | strict; no image upload |
| **zero-traffic-runtime** (5) | future operator-run Cloud Run revision gate | — | not executed in E12 |
| **canary-promotion** (6) | future controlled-traffic decision | — | not executed in E12 |

## 5. Strict status semantics

Check states: `pass`, `fail`, `warning`, `skipped`, `unavailable`, `infrastructure-error`,
`not-applicable`. For release tiers (3–6) a required `warning`/`skipped`/`unavailable`/
`infrastructure-error` is a release FAILURE — there is **no** `pass_with_warnings` release-eligible
decision. A missing required check is treated as a failure (it can never silently disappear). A hard
defect can never be downgraded by a score. Final decision ∈ `pass | fail | blocked |
infrastructure-failure`; `releaseReady` is true only when decision is `pass`, every required check
passed, there are zero private-artifact leaks and zero unresolved hard defects.

## 6. Generated corpus (20 families)

native-prose, multi-page-native, adjacent-complex-tables, multi-row-header-table, chart-heavy,
mixed-chart-table-text, branded-brochure, unavailable-font, typography-ranges, image-only-scan,
rotated-page, rtl-complex-script, formula-and-code, blank-near-blank, twenty-five-page, eighty-page,
**pre-upgrade-failure-class (the 57/100 class)**, safe-raster-only, provider-conflict, cache-replay.

Each family is a `GeneratedFixtureSpecV1` + an **independent** `GoldenExpectedTruthV1`. Identity derives
from `(fixtureId, sourceBuilderVersion, seed)` — no time, no random id, no network.

## 7. Generated PDF builders

`sourcePdfBuilders.ts` builds REAL source PDFs at runtime with `pdf-lib`, deterministically (fixed fonts,
coordinates and **epoch metadata**), so the same fixture always yields the same bytes and source
SHA-256 (proven in the e2e). Generated bytes stay in-memory / an ignored temp scope; no PDF/PNG binary
is committed.

## 8. Expected truth is independent

Expected truth is emitted by the fixture definition, never derived from the extracted candidate. The
assertion engines compare ACTUAL output to that truth: page count/dimensions/rotation, region
counts/types/ownership, critical Unicode + numeric tokens, chart visibility, table native-or-crop with
zero wrong-cell/generic-header/clip, single visible owner.

## 9. End-to-end runner + real e2e

`tests-e2e/pdf-extraction-v3/generated-corpus.e2e.ts` proves the real path with actual implementations:
real source PDF (pdf-lib) → candidate template → **real E6 render in Chromium** (`renderTemplateToHtml`)
→ **real DOM evidence** (text present, non-zero layout, computed style) → **real browser raster**
(non-blank screenshot) → **real jsPDF export** (`renderTemplateToBlob`) → **real export re-parse**
(pdf-lib re-reads the exported bytes: page count + dimensions) → deterministic double-run. Remote
providers / Document AI / VLM / heavy targets stay unavailable and are never invoked.

Pixel-level PDF re-raster of the exported bytes is best-effort (headless Chromium PDF rendering may be
unavailable); the structural export re-parse is the authoritative export verification, and the pixel
attempt is recorded, never faked — matching the repo's existing `export_rasterization_unavailable`
handling.

## 10. Hard release thresholds

Critical page/region coverage = 100%; unresolved hard defects = 0; blocked pages = 0; chart/picture
visibility = 100%; zero blank required crops / duplicate representations / wrong-cell associations /
missing rows-columns / generic headers / clipped rows; critical Unicode/numeric/punctuation recall =
100%; overall visible-text recall ≥ 99%; generated score ≥ 0.92 (complex ≥ 0.95); browser/export parity
= 100%; repair passes ≤ 2, zero introduced hard defects; zero remote-provider attempts (generated
tiers); zero V1/V2 cache hits for V3; artifact completeness = 100%; zero private-artifact leaks / signed
URLs persisted. Fallback (exact crop / raster) is a valid success only when explicit, source-backed,
artifact-complete and E7-verified.

## 11. Determinism, baselines, performance, cost

**Determinism**: two identical runs must match on exact identity fields (plan id/hash, fingerprint,
region/candidate/run keys, output strategies, hard-defect sets) and metrics within tolerance;
timestamps/URLs excluded; a semantic mismatch is a hard failure. **Baselines**: environment-profile
scoped, never self-updating; a proposal built on a result with hard defects is rejected; threshold
reductions are flagged and require separate approval. **Performance**: one absolute safety ceiling +
an environment-matched relative-regression limit (default 20%); a required-but-missing baseline is
`unavailable` → gate failure. **Cost**: generated tiers use zero billable provider; unknown cost is
never zero; a remote attempt with unknown cost cannot pass a cost-approval tier.

## 12. Private corpus + resolver

The private registry holds only opaque ids + hashes + approved metadata — never a source path,
filename, signed URL, extracted text or private value. Source bytes are fetched through an INJECTED
resolver that blocks fork/untrusted/unauthorized contexts, verifies the hash before use, returns a
runtime-only handle and guarantees cleanup — never a persisted signed URL. A fake resolver is used in
tests; the real one is wired only in the protected, manually-dispatched workflow. E12 does not run the
real private corpus.

## 13. Private-artifact scanner V2

`artifact-scan.mjs` fails on committed PDF/image/font/model binaries (outside the approved generated
temp scope), signed/blob/data URLs, bearer tokens, credentials, Document AI processor resources, Cloud
Run endpoints and `.env` files — across staged files, tracked files or a named directory (including
report dirs; no blanket report-dir exclusion). The scanner's own pattern-definition files are exempt
from the text scan only (still media-scanned) — a targeted, documented exemption.

## 14. CLI + CI

`npm run pdf-import:v3:gate:{static,fast,full}` exit 0 ONLY on a release-ready pass; there is no
`--force-pass` / `--skip-quality` / `--ignore-hard-defects` (all rejected). `--no-build`/`--no-tests`
are developer-diagnostic and force `releaseReady=false`. The `pdf-extraction-v3-gates.yml` workflow runs
static+fast on PRs (fork-safe, no private secrets), generated-full on main push + nightly, and a
protected manual private-controlled job (no fork access, sanitized reports, private secret never
uploaded). Least-privilege `permissions: contents: read`.

## 15. Contract matrix

`contractMatrix.ts` records every E0–E12 contract (producer, consumer, fingerprint inclusion, release
checks). The gate fails when a required contract is missing or a version disagrees; the V3 cache
fingerprint is a required fingerprint contract.

## 16. Security & privacy

No committed private PDFs/images/text; no signed URL / credential in any report; server authority
untouched; remote providers / Document AI / VLM remain disabled; readiness for runtime/canary/promotion
stays `null` (not `false`) until operator-run evidence exists.

## 18. Acceptance thresholds (code package)

Review-ready when: E11 merged; generated fast gate passes; generated full gate passes in a capable
environment; all 20 families registered with independent truth; the real browser + export path executes
(proven here); strict semantics enforced; hard-defect-first; no V1/V2 cache for V3; deterministic
replay; 25/80-page fixtures registered; zero private-artifact leaks / signed URLs; zero remote attempts.
Private corpus + runtime/canary readiness remain `null` until separately executed — never reported as
passed.

## 19. Known limitations

- The `generated-full` browser gate (25/80-page real-browser runs) and the local Docker container gate
  require a capable CI environment; in this code environment the full-tier `runtime.container` /
  large-document browser runs are `unavailable` → the full tier is correctly NOT release-ready here.
  The **generated-fast** real browser + export e2e DID execute and pass.
- Pixel-level export re-raster depends on a PDF rasterizer (`pdfjs-dist` not installed); the structural
  export re-parse is authoritative and the pixel attempt is recorded, never faked.
- The private 13-page report is NEVER committed and is exercised only through the later operator-run
  private-controlled gate.

## 20. Deployment scope

No migration, no Edge Function deploy, no Cloud Run / Google Cloud / IAM / Secret / API change, no
remote/multi-service activation, no production data mutation, no `gcloud`. See the release-candidate
runbook for the operator-owned deployment sequence.
